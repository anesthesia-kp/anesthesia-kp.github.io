9. **Ask of every build that adds a page or a control: what would still pass if the whole thing were INERT?** If "everything", the gate is the wrong shape. Such a build ships with something that DRIVES it — a browser suite that clicks, or at minimum the render harness. (Build 88, FAST-1.)
10. **Test the code, not the prose — an assertion that cannot fail is a false one — and prove the stripper kept the code.** A `/*` inside a LINE comment opens a block comment that ran to 70% of the schedule admin: strip line comments first, then block comments, and assert what survived. Strip comments before any textual assertion; make the search window reach the line. **Stub the SHAPE of the real function, never the convenience.**
11. **Read an exit code directly, never through a pipe** (`… | tail` reports tail's status). Make a MISSING function, DOM element or assertion-message input report a legible FAILURE — never a throw, and **never a PASS: an assertion that cannot tell the good state from the ABSENT one is not an assertion** (14 Sep: a new no-tilt check went green on a page carrying no photo at all — `transform` was `null` and the angle was initialised to `0`). The honesty run is where absence lives.
12. **When a suite must be edited to pass, ask which you are changing: what is TRUE, or what is ASSERTED.** Repoint an assertion whose target moved; replace one whose premise the build changed with an INVARIANCE the previous build fails. Never stub the new behaviour.
13. **The pasted governing document is a snapshot; the disk copy is the document.** Read from disk, and fetch before reading.
14. **A concession is worth no more than the claim it replaced** — *run it, don't recall it* governs Claude's agreements as much as its assertions. Before building or asking anything, **check whether the code already answers it.** Where Claude changes its position on evidence, say so and date it.
15. **Write patches that refuse to apply twice** — assert `count(old)==1` before substituting; md5 both sides after any interruption. **Verified base → ship the file; unverified base → ship the patch.**
16. **An assertion that pins a count or a quoted string decays into a no-op as the code moves. Assert the INVARIANT** — re-anchored suites come out STRICTER than what they replaced.
17. **After an owner-found defect, HUNT THE CLASS before fixing the instance** — *"are there other things hiding with the same problem?"* Name the structural cause, then inventory every call site that shares it; the fix's audit brief carries that hunt.
