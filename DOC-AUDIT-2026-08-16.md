# PART 3 — THE STRUCTURAL PROBLEM

Parts 1 and 2 are symptoms. This is the disease, and fixing the symptoms without fixing this
means doing the whole audit again in three weeks.

**The project's own standard is "a fact has ONE home."** It is not being met. Here is where
each kind of fact actually lives today:

| fact | homes | agree? |
|---|---|---|
| Schedule build numbers + push state | `START-HERE.md` §2 · `HANDOFF.md` ×3 places · `schedule/TODO.md` · `BUILD-LOG.md` | **No.** START-HERE says 63/28 live. HANDOFF and TODO carry a byte-identical table saying 51/52 and 26/27 "NOT pushed". BUILD-LOG marks builds 60–63 "not pushed yet". |
| Auction build numbers | `START-HERE.md` · `HANDOFF.md` ×3 · `vacation TODO.md` | **No.** HANDOFF line 128 says admin 239 / index 127 / mobile 16, marked as verified. |
| Auction battery size | 6 places | **No.** 1,074 in four, 1,075 in two. The itemised list sums to 1,075. |
| Which rulings exist | `DECISIONS.md` · `HANDOFF.md`'s index · `schedule/TODO.md`'s answered table | **No.** The index stops 12 rulings short. |
| What has shipped | `BUILD-LOG.md` · `TODO.md` roadmap · 4 design docs · `SCHEDULE-FOUNDATIONS-SPEC.md` | **No.** See Part 4.2. |
| Where the commit message goes | `START-HERE.md` (`COMMIT-MESSAGE.txt`) · `HANDOFF.md` and `BUILD-LOG.md` (`.claude-commit-msg.txt`) | **No.** The dotfile scheme was retired *because* the leading dot hid it — and two documents still teach it. The three dotfiles they name do not exist. |

**Why this keeps happening:** every one of these facts is *derivable* or *dated*, and none of
them is generated. Build numbers are in `versions.json`. Suite counts are `ls | wc -l`.
Assertion counts come out of a battery run. Push state is one read-only git command. They are
being maintained by hand, in five places, by a process that is careful but not perfect —
and each copy rots independently.
